# 入金消込AI Agent デモ

経理部門向け「入金消込自動化システム」の**営業デモ**アプリです。
販売管理システム（基幹）から連携された**計上済み売掛金の未消込債権一覧**と、銀行のFBデータ
（全銀フォーマットの入金明細）をAIが突合し、
「自動消込 → 目検 → 督促 → 上長承認 → 仕訳生成・経理システム連携 → 監査証跡」までの
一連の業務を、クリック操作で見せられます。

> ⚠️ 営業デモ用アプリです。基幹連携・銀行API・メール送信・経理システム連携は実接続しません（UI上にはデモ/モックの表記を出さない方針）。
> ただし突合エンジン（`lib/matching.ts`）は実ロジックで動作します。ボタンを押すと本当に突合が走り、結果が分類されます。

姉妹デモ: [order-intake-ai-demo（受注取り込みAI）](../order-intake-ai-demo) と同じ設計思想・デザインシステム（PMGライト）で実装しています。

## 業務上の位置づけ

- 売掛金は**請求時点で既に計上済み**。本システムは債権を新規計上するのではなく、
  販売管理システム（商奉行クラウド）から**未消込債権の一覧を同期**し、入金を当てていく
- 取引先は**マスタとして保持**し、販売管理システムと同期。**1取引先（顧客ID）に対して複数の振込名義**
  （正規名義・旧社名・カナ別名・個人名義・学習済み）をレコードとして紐づける
- 消込で生成された仕訳（借方: 普通預金＋支払手数料／貸方: 売掛金＋仮受金）は、
  **経理システム（勘定奉行クラウド）への連携**またはCSVで引き渡す

## 起動方法（ローカル）

```bash
npm install      # 初回のみ
npm run dev      # → http://localhost:3400
```

ローカルは `.env.local` の `APP_PASSWORD` でログインします（初期値: `localtest123`）。
ブラウザで <http://localhost:3400> を開きます。

## 画面構成

| 画面 | URL | 内容 |
|---|---|---|
| ダッシュボード | `/` | 消込率・要確認・未入金・工数削減のKPI、消込率ゲージ、エイジンググラフ、直近アクティビティ、月次レポートCSV |
| データ取込 | `/import` | 販売管理システムからの**債権データ連携**（未消込債権30件の同期・重複伝票スキップ／欠損補完の整合性チェック付き）。FBデータ取得→全銀フォーマット生データのプレビュー→パース＆名義正規化 |
| 突合結果 | `/matching` | 「自動突合を実行」→ AI処理演出 → 消込済み（緑）/ 要目検（黄）/ 保留（グレー）/ 督促対象（赤）のタブ別一覧。マスタ学習後の再突合も可能 |
| 目検キュー | `/review` | 要目検・保留案件の「請求情報 vs 入金情報」左右比較、AI判断理由の自然言語表示、承認/差戻し/別候補選択、振込名義の**取引先マスタ登録**チェックボックス |
| 督促管理 | `/dunning` | 未入金一覧、AIによる督促メール自動生成→編集→送信、送信/開封/返信のトレース、基準日コントロールで7日→再督促・14日→エスカレーション |
| 承認 | `/approval` | 閾値（初期10万円）以上の値引・振替処理の上長承認。ロール切替（担当者⇔上長）は全画面ヘッダーに配置。承認/却下/コメント付き差戻し |
| 取引先マスタ | `/customers` | 販売管理システムと同期。顧客ID・正式名・代表者・**振込元口座**と、**1顧客 : N振込名義**のレコード管理（マスタ本体は編集不可・振込名義のみ追加/削除可） |
| 消込ログ・監査 | `/audit` | 消込ログ（実行者・日時・照合根拠・スコア）、仕訳データ（借方/貸方・**経理システムへ連携ボタン＋連携状態**）、操作タイムライン（検索・実行者フィルタ）。各CSVダウンロード |

## おすすめのデモ手順（約4〜5分）

1. **ダッシュボード**（`/`）— 未消込債権30件・消込率0%の状態を確認
2. **データ取込**（`/import`）—「債権データを同期」→ 販売管理システムから債権レコードが流れ込み、
   30件を台帳へ同期（重複伝票1件スキップ・欠損補完1件の警告バッジ）
3. 同画面で「FBデータ取得」→ 全銀フォーマットの生データ → パース後25件（正規化とマスタ照合を表示）
4. **突合結果**（`/matching`）—「自動突合を実行」→ 数秒の処理演出の後、
   自動消込18 / 要目検6 / 保留1 / 督促対象5 に分類される
5. **目検キュー**（`/review`）— 名義ゆれ「カ)イトウチユウ」を開き、AI判断理由を確認 →
   「この振込名義を取引先マスタに登録する」にチェックのまま「承認して消込」→ 学習トースト表示
6. **取引先マスタ**（`/customers`）— 伊藤忠商事に「学習済み」名義が追加されたことを確認
7. **督促管理**（`/dunning`）— 1件選んで「AIで督促メールを作成」→ 文面を編集 → 「送信する」
   → 状況更新トグルと基準日コントロール（⏩7日進める）で再督促・エスカレーションを見せる
8. **目検キュー**に戻り、過入金（カ)ゼンリン・差額¥132,000）を「差額を仮受金へ振替して消込」
   → 10万円以上のため**上長承認へ回付**される
9. 画面右上のロール切替で**上長（田中）**へ →**承認**（`/approval`）で「承認する」→ 消込・仕訳が実行される
10. **消込ログ・監査**（`/audit`）— 仕訳データタブで「**経理システムへ連携**」→ 全仕訳が連携済みに。
    消込ログ・操作タイムラインで一連の証跡を表示
11. **ダッシュボード**に戻る → 消込率が上昇、KPI・グラフが更新されている
12. 左下「↺ 初期状態に戻す」でいつでも最初の状態に戻せます

## 突合エンジンの判定ロジック（`lib/matching.ts`・純粋関数）

名義照合は**取引先マスタの振込名義レコード（payerAliases）**に基づいて行います。

| ルール | 条件 | スコア | 分類 |
|---|---|---|---|
| B-1 完全一致 | 正規名義一致 × 金額完全一致 × 期日±5営業日 | 100 | 自動消込（緑） |
| B-2 手数料差 | 金額差が110/220/330/440/660/880円 × 名義一致 | 95 | 自動消込・手数料控除仕訳 |
| B-3 あいまい名義 | 前方一致・部分一致・カナゆれ × 金額一致 | 60〜85 | 要目検（黄） |
| B-3 マスタ別名 | マスタの旧社名・カナ別名レコードと一致 × 金額一致 | 82 | 要目検 |
| B-4 合算入金 | 同一名義の複数債権の合計と入金額が一致 | 85 | 要目検（組み合わせ提示） |
| 複合 | 名義ゆれ + 手数料差 | 〜75 | 要目検 |
| 個人名義 | 振込名義がマスタの代表者名と一致 | 70 | 要目検 |
| B-5 過入金 | 名義一致 × 入金 > 請求 | 62 | 要目検（差額振替は承認フローへ） |
| B-5 不明入金 | どの債権とも紐付かない | — | 保留（グレー） |
| B-6 未入金 | 期日超過 × 入金なし | — | 督促対象（赤）・エイジング分類 |

分類ルール: **スコア95以上=自動消込 / 60〜94=要目検 / 紐付けなし=保留 / 期日超過未入金=督促対象**

目検で名義を確定しマスタ登録すると `learned`（学習済み）の振込名義レコードが追加され、
**次回の突合から自動一致（スコア100）** になります。

## モックデータ（`lib/data.ts`）

- 取引先マスタ29社（顧客ID CUST-001〜）。取引先・銀行には実在の名称をサンプルとして使用（債権・入金・口座などの数値はすべて架空）。正式名義29件＋実際の旧社名3件（松下電器産業→パナソニック等）の振込名義と振込元口座を初期登録
- 債権30件（3万〜80万円・売上伝票番号付き）、入金25件。日付は**今日を基準に相対生成**
- 入金ケース内訳: 完全一致14 / 手数料差4（-220円・-440円） / 名義ゆれ2（カナ略記・旧社名） / 合算1（2債権を1振込） / 名義ゆれ+手数料1 / 不明1 / 過入金1（+13.2万円→承認デモ用） / 個人名義1（代表者振込）
- 未入金5件はエイジング（〜30日/31〜60日/61日〜）に分散
- 取引先名・金額を差し替えれば、商談相手に合わせたデモにカスタマイズできます

## 技術構成

- Next.js 14（App Router）/ React 18 / TypeScript
- Tailwind CSS（order-intake-ai-demo と同一のPMGライト・デザイントークン）
- Zustand（デモ状態のクライアント管理。リロード/リセットで初期化）
- チャート・アニメーションは外部ライブラリ非依存の自前実装
- 共有パスワード認証（HMAC署名Cookie・Edgeミドルウェア）— Vercel等へ公開する場合は
  環境変数 `APP_PASSWORD` / `AUTH_SECRET` を設定
