# 入金消込AI Agent デモ

経理部門向け「入金消込自動化システム」の**営業デモ**アプリです。
請求書から作成した債権台帳と、銀行のFBデータ（全銀フォーマットの入金明細）をAIが突合し、
「自動消込 → 目検 → 督促 → 上長承認 → 仕訳・監査証跡」までの一連の業務を、クリック操作で見せられます。

> ⚠️ 本番システムではありません。銀行API・メール送信・会計システム連携はすべて**モック**です。
> ただし突合エンジン（`lib/matching.ts`）は実ロジックで動作します。ボタンを押すと本当に突合が走り、結果が分類されます。

姉妹デモ: [order-intake-ai-demo（受注取り込みAI）](../order-intake-ai-demo) と同じ設計思想・デザインシステム（PMGライト）で実装しています。

## 起動方法（ローカル）

```bash
npm install      # 初回のみ
npm run dev      # → http://localhost:3400
```

ローカルは `.env.local` の `APP_PASSWORD` でログインします（初期値: `localtest123`）。
ブラウザで <http://localhost:3400> を開きます。

## 画面構成

| 画面 | URL | 内容 |
|---|---|---|
| ダッシュボード | `/` | 消込率・要確認・未入金・工数削減のKPI、消込率ゲージ、エイジンググラフ、直近アクティビティ、月次レポートCSV |
| データ取込 | `/import` | 請求書フォルダ（31ファイル）→取込実行で債権台帳30件を登録（重複スキップ・欠損補完の警告付き）。FBデータ取得→全銀フォーマット生データのプレビュー→パース＆名義正規化 |
| 突合結果 | `/matching` | 「自動突合を実行」→ AI処理演出 → 消込済み（緑）/ 要目検（黄）/ 保留（グレー）/ 督促対象（赤）のタブ別一覧。辞書学習後の再突合も可能 |
| 目検キュー | `/review` | 要目検・保留案件の「請求情報 vs 入金情報」左右比較、AI判断理由の自然言語表示、承認/差戻し/別候補選択、名義ゆれの辞書登録チェックボックス |
| 督促管理 | `/dunning` | 未入金一覧、AIによる督促メール自動生成→編集→送信（モック）、送信/開封/返信のトレース、デモ内時計で7日→再督促・14日→エスカレーション |
| 承認 | `/approval` | 閾値（初期10万円）以上の値引・振替処理の上長承認。ロール切替（担当者⇔上長）は全画面ヘッダーに配置。承認/却下/コメント付き差戻し |
| 消込ログ・監査 | `/audit` | 消込ログ（実行者・日時・照合根拠・スコア）、仕訳データ（借方/貸方）、操作タイムライン（検索・実行者フィルタ）。各CSVダウンロード |
| 設定 | `/settings` | 承認金額閾値、手数料許容値（110〜880円）、名義ゆれ辞書の閲覧・追加・削除 |

## おすすめのデモ手順（約4〜5分）

1. **ダッシュボード**（`/`）— 未消込債権30件・消込率0%の状態を確認
2. **データ取込**（`/import`）—「取込実行」→ 請求30件が債権台帳に登録（重複1件スキップ・欠損補完1件の警告バッジ）
3. 同画面で「FBデータ取得」→ 全銀フォーマットの生データ → パース後25件（正規化前後の名義を表示）
4. **突合結果**（`/matching`）—「自動突合を実行」→ 数秒の処理演出の後、
   自動消込18 / 要目検6 / 保留1 / 督促対象5 に分類される
5. **目検キュー**（`/review`）— 名義ゆれ「カ)アルフア」を開き、AI判断理由を確認 →
   「この名義ゆれを辞書に登録する」にチェックのまま「承認して消込」→ 学習トースト表示
6. **督促管理**（`/dunning`）— 1件選んで「AIで督促メールを作成」→ 文面を編集 → 「送信する（モック）」
   → デモ操作トグルとデモ内時計（⏩7日進める）で再督促・エスカレーションを見せる
7. **目検キュー**に戻り、過入金（カ)タウデンシ・差額¥132,000）を「差額を仮受金へ振替して消込」
   → 10万円以上のため**上長承認へ回付**される
8. 画面右上のロール切替で**上長（田中）**へ →**承認**（`/approval`）で「承認する」→ 消込・仕訳が実行される
9. **ダッシュボード**に戻る → 消込率が上昇、KPI・グラフが更新されている
10. **消込ログ・監査**（`/audit`）— 消込ログ・仕訳・操作タイムラインで一連の証跡を表示
11. 左下「↺ デモをリセット」でいつでも最初の状態に戻せます

## 突合エンジンの判定ロジック（`lib/matching.ts`・純粋関数）

| ルール | 条件 | スコア | 分類 |
|---|---|---|---|
| B-1 完全一致 | 正規化後名義一致 × 金額完全一致 × 期日±5営業日 | 100 | 自動消込（緑） |
| B-2 手数料差 | 金額差が110/220/330/440/660/880円 × 名義一致 | 95 | 自動消込・手数料控除仕訳 |
| B-3 あいまい名義 | 前方一致・部分一致・カナゆれ × 金額一致 | 60〜85 | 要目検（黄） |
| B-3 旧社名辞書 | 名義ゆれ辞書（旧社名）と一致 × 金額一致 | 82 | 要目検 |
| B-4 合算入金 | 同一名義の複数請求の合計と入金額が一致 | 85 | 要目検（組み合わせ提示） |
| 複合 | 名義ゆれ + 手数料差 | 〜75 | 要目検 |
| 個人名義 | 振込名義が請求先の代表者名と一致 | 70 | 要目検 |
| B-5 過入金 | 名義一致 × 入金 > 請求 | 62 | 要目検（差額振替は承認フローへ） |
| B-5 不明入金 | どの請求とも紐付かない | — | 保留（グレー） |
| B-6 未入金 | 期日超過 × 入金なし | — | 督促対象（赤）・エイジング分類 |

分類ルール: **スコア95以上=自動消込 / 60〜94=要目検 / 紐付けなし=保留 / 期日超過未入金=督促対象**

目検で名義を確定し辞書登録すると `learned`（学習済み）エントリが追加され、**次回の突合から自動一致（スコア100）** になります。

## モックデータ（`lib/data.ts`）

- 請求30件（3万〜80万円・すべて架空の日本企業）、入金25件。日付は**今日を基準に相対生成**
- 入金ケース内訳: 完全一致14 / 手数料差4（-220円・-440円） / 名義ゆれ2（カナ略記・旧社名） / 合算1（2請求を1振込） / 名義ゆれ+手数料1 / 不明1 / 過入金1（+13.2万円→承認デモ用） / 個人名義1（代表者振込）
- 未入金5件はエイジング（〜30日/31〜60日/61日〜）に分散
- 名義ゆれ辞書の初期データ3件（旧社名→現社名など）
- 取引先名・金額を差し替えれば、商談相手に合わせたデモにカスタマイズできます

## 技術構成

- Next.js 14（App Router）/ React 18 / TypeScript
- Tailwind CSS（order-intake-ai-demo と同一のPMGライト・デザイントークン）
- Zustand（デモ状態のクライアント管理。リロード/リセットで初期化）
- チャート・アニメーションは外部ライブラリ非依存の自前実装
- 共有パスワード認証（HMAC署名Cookie・Edgeミドルウェア）— Vercel等へ公開する場合は
  環境変数 `APP_PASSWORD` / `AUTH_SECRET` を設定
